# testTool SOP：接口时延 P99 指标与 Prometheus/Grafana 对接

接口时延（任务提交→完成的往返）分布指标：本地按周期打印 P99 分位行（总口径 + 分接口分列），并可选开启 Prometheus 抓取端点（`/metrics` 文本协议），接入本地 Prometheus + Grafana 看板。

## 第一部分：P99 分位行

- **打印行**（指标线程输出，独立于 1s 窗口行）：

  ```
  Scheduler latency P99 [10s]: total=5.907ms exist=3.406ms put=5.907ms get=3.739ms delete=3.282ms
  ```

- **配置键**（`conf/test_config.conf`，均可缺省——存量 conf 副本不含键时取默认值）：

  ```ini
  p99_interval_s = 10      # 打印间隔（秒）；0 禁用
  ```

- **口径**：任务级时延样本（每任务一个：提交→完成），每执行器每接口滚动保留最近 8192 个样本，分位按 nearest-rank 法取 `ceil(0.99×n)` 位样本；间隔内样本超出容量时等效最近样本滚动窗口（长稳监控足够平滑）。无样本接口显示 `-`

## 第二部分：Prometheus 抓取端点

- **配置键**（可缺省，默认关闭）：

  ```ini
  metrics_exporter = off       # on 启动 HTTP /metrics 端点（POSIX 平台；启动失败 fail-fast 退出）
  metrics_exporter_port = 9450 # 监听端口（1-65535）
  ```

- **指标族**（前缀 `testtool_`，exposition format 0.0.4）：

  | 指标 | 类型 | 说明 |
  | --- | --- | --- |
  | `testtool_io_duration_seconds{op,quantile}` | summary | 分接口时延分位（P50/P90/P99；无样本接口不输出分位行）+ `_sum` / `_count` |
  | `testtool_ops_total{op}` | counter | 分接口操作数（entry 级全量口径） |
  | `testtool_io_bytes_total{op}` | counter | 分接口流量字节（成功 entry 口径，应用层完成带宽） |
  | `testtool_errors_total` | counter | 失败操作数（不含 NOT_FOUND 观察） |
  | `testtool_notfound_total` | counter | NOT_FOUND 观察计数 |
  | `testtool_uptime_seconds` | gauge | 运行时长 |

- **抓取验证**（工具运行中）：

  ```bash
  curl http://<testTool 主机>:9450/metrics
  ```

## 第三部分：Prometheus + Grafana 对接

**prometheus.yml 增加抓取任务**（重载 Prometheus 配置：`curl -X POST http://<prometheus>:9090/-/reload`）：

```yaml
scrape_configs:
  - job_name: 'testtool'
    scrape_interval: 15s
    static_configs:
      - targets: ['<testTool 主机 IP>:9450']
```

**Grafana**：数据源指向该 Prometheus（`testtool_*` 指标自动可见），常用 PromQL：

| 看板项 | PromQL |
| --- | --- |
| 分接口 P99 时延 | `testtool_io_duration_seconds{quantile="0.99"}`（按 `op` legend 分列） |
| 分接口 IOPS | `sum by (op) (rate(testtool_ops_total[30s]))` |
| 分接口带宽 | `sum by (op) (rate(testtool_io_bytes_total[30s]))` |
| 错误 / 未命中速率 | `rate(testtool_errors_total[30s])`（notfound 同款） |

**带宽口径提醒**：`testtool_io_bytes_total` 与日志 `traffic` 同为 **IO 完成口径**（应用层真实完成带宽，非注入计数；限速 `ratelimit_mb` 是注入控制，两者对照反映链路积压）；线路级占用（协议帧头 / RDMA transport 开销）需系统级计数观察，详见 sop/5 第三部分。

## 第四部分：常见问题

| 现象 | 处理 |
| --- | --- |
| 启动报 `metrics exporter listen on port ... failed` | 端口被占（conf 改 `metrics_exporter_port`）或权限不足（换 >1024 端口）；fail-fast 退出属预期 |
| P99 行不出现 | `p99_interval_s=0` 为禁用；或运行时长不足一个打印间隔（间隔与 runtime 至少 1:1，长稳建议 interval ≤ runtime/2） |
| `/metrics` 某接口无分位行 | 该接口无完成样本（无样本不输出 quantile 行，`_count` 为 0 可查） |
| P99 数值与 1s 窗口 avg TTFT 差异大 | 正常：avg 是全部任务平均、P99 是分布尾部分位；长尾（偶发慢请求）只反映在 P99 |
| 存量 conf 未写新键 | 兼容：`p99_interval_s` 默认 10、`metrics_exporter` 默认 off、端口默认 9450 |
| 多实例同机抓取 | 每实例配独立 `metrics_exporter_port`，Prometheus targets 逐实例列出，Grafana 按 `instance` label 区分 |
