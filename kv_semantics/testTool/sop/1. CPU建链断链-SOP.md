# 1. CPU 建链断链 SOP

CPU-over-RoCE 建链 / 断链验证的简明操作步骤。详细原理与排障见 `demo/SOP-build-and-run.md`。

前置：对端存储M800、M900 已就绪（监听端口可达，store 侧 RoCE 配置 `asu_roce_*` 前缀已按环境就位，参考 `kv_semantics/docs/guide/roce-provider.md`）。

## 1. 编译

在 testTool 目录下执行一键脚本（编译 kv client + testTool，链接自动接好）：

```bash
bash demo/scripts/build-cpu-roce.sh
```

- 前置依赖缺失时脚本会报错并给出安装提示（cmake / g++ / python3 / libibverbs-dev）
- 首次编译需联网拉取 fmt / spdlog
- 产物：`build/testTool`（kv client 库在 `../build-kv/src/`）

## 2. 修改配置文件

| 文件 | 改什么 |
|---|---|
| `demo/conf/kv_client_real.conf` | ① `asu_info.N` 的 IP / port 改为对端 KV store 实际地址；② `transport.roce_*` 段取消注释按环境改值（**必填 `transport.roce_gid_index`**，其余缺省可用）；`provider_type=CPU` 已配好 |
| `demo/conf/kv_client_view_real.conf` | **必须与 conf 同步改**：`asuIds` 与 `asu_info.N` 两边字段完全一致——**建链端点最终以 view 文件为准**，view 没列的节点静默不建链 |
| `demo/conf/test_config_onlyconnect.conf` | 建链验证用默认值即可；断链测试改 `autodisconnect`（见第 4 步） |

## 3. 启动（建链验证）

```bash
./build/testTool demo/conf/test_config_onlyconnect.conf demo/conf/kv_client_real.conf
```

- 建链成功标志：`onlyconnect=on: connection established, waiting for Ctrl+C to exit...`（N 个节点全部建链成功才会挂起；任一节点失败直接报错退出）
- 结束：`Ctrl+C`（日志出现 `Ctrl+C received, exiting`，优雅断链后退出）

## 4. 断链与观察

`demo/conf/test_config_onlyconnect.conf` 中：

```properties
autodisconnect = 30   # 0: 禁用；>0: 建链成功 n 秒后自动断链（先注销 region、发断链协议帧、销毁 QP，对端 store 可感知）
```

- 自动断链后**进程不退出**，继续挂起供观察断链后两侧状态（对端 store 日志、QP 残留、TCP 连接）
- 观察完毕 `Ctrl+C` 退出

## 5. 日志级别

| 日志 | 怎么开 |
|---|---|
| testTool 自身日志 | `test_config_onlyconnect.conf` 的 `log.level`（debug / info / warn / error） |
| **kv client 建链日志**（AddGroup 端点、失败原因） | **环境变量 `KV_LOG_LEVEL=debug`**（缺省 info，建链排障必开）；同时打印到控制台与 `kv_log/kv-<pid>.log` |

建链排障启动方式：

```bash
KV_LOG_LEVEL=debug ./build/testTool demo/conf/test_config_onlyconnect.conf demo/conf/kv_client_real.conf
```

失败报错读法：`AddGroup FAILED` 里 `Connection refused` = 对端无监听 / 端口打重；`timed out` = 对端未就绪或网络不通；`queue pair ...` = OOB 通了、RDMA 层（gid / 路由）问题。
