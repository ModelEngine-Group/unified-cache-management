# 1. CPU 建链断链 SOP

CPU-over-RoCE 建链 / 断链验证的简明操作步骤。详细原理与排障见 `sop/0.build-and-run-sop.md`。

前置：对端存储M800、M900 已就绪（监听端口可达，store 侧 RoCE 配置 `asu_roce_*` 前缀已按环境就位，参考 `kv_semantics/docs/guide/roce-provider.md`）。

## 1. 编译

在 testTool 目录下执行一键脚本（编译 kv client + testTool，链接自动接好；FAKE 模拟与 RoCE 真链路双 provider 一并编入，conf 改 `transport.provider_type` 即在两者间切换无需重编；CPU 链路为脚本缺省模式，与 NPU SOP 共用同一脚本，详见 `scripts/build-kv-link.sh` 头部说明）：

```bash
bash scripts/build-kv-link.sh                      # 缺省 CPU 模式 + Release（产物可随时性能测试）
bash scripts/build-kv-link.sh --build-type debug   # 调试构建（断点 / 单步）时显式声明
```

- 前置依赖缺失时脚本会报错并给出安装提示（cmake / g++ / python3 / libibverbs-dev）
- 首次编译需联网拉取 fmt / spdlog
- 产物：`build/testTool`（kv client 库在 `../build-kv/src/`）

## 2. 修改配置文件

复制默认 conf 为独立副本（不动仓库默认文件）：

| 文件 | 改什么 |
|---|---|
| kv client 副本（复制 `conf/kv_client.conf`） | ① `asu_info.N` 的 IP / port 改为对端 KV store 实际地址（**单文件模式：建链端点即副本 `asu_info.N`，无独立 view 文件**）；② `transport.roce_*` 模板段取消注释按环境改值（**必填 `transport.roce_gid_index`**，未配置启动直接报错；其余缺省可用——`roce_hca_name` 缺省自动选第一个 RDMA 设备，不可用时启动报错，建议显式指定可用设备名）；③ `transport.provider_type` 改 `CPU` |
| test conf 副本（复制 `conf/test_config.conf`） | `onlyconnect = on`（建链验证不下 IO）；断链测试再改 `autodisconnect`（见第 4 步） |

## 3. 启动（建链验证）

```bash
./build/testTool <test conf 副本> <kv client 副本>
```

- 建链成功标志：`onlyconnect=on: connection established, waiting for Ctrl+C to exit...`（N 个节点全部建链成功才会挂起；任一节点失败直接报错退出）
- 结束：`Ctrl+C`（日志出现 `Ctrl+C received, exiting`，优雅断链后退出）

## 4. 断链与观察

test conf 副本中：

```properties
autodisconnect = 30   # 0: 禁用；>0: 建链成功 n 秒后自动断链（先注销 region、发断链协议帧、销毁 QP，对端 store 可感知）
```

- 自动断链后**进程不退出**，继续挂起供观察断链后两侧状态（对端 store 日志、QP 残留、TCP 连接）
- 观察完毕 `Ctrl+C` 退出

## 5. 日志级别

| 日志 | 怎么开 |
|---|---|
| testTool 自身日志 | test conf 副本的 `log.level`（debug / info / warn / error） |
| **kv client 建链日志**（AddGroup 端点、失败原因） | **环境变量 `KV_LOG_LEVEL=debug`**（缺省 info，建链排障必开）；同时打印到控制台与 `kv_log/kv-<pid>.log` |

建链排障启动方式：

```bash
KV_LOG_LEVEL=debug ./build/testTool <test conf 副本> <kv client 副本>
```

失败报错读法：`AddGroup FAILED` 里 `Connection refused` = 对端无监听 / 端口打重；`timed out` = 对端未就绪或网络不通；`queue pair ...` = OOB 通了、RDMA 层（gid / 路由）问题。`roce_gid_index is required` = 必填键未配置。`no RDMA device found` = 本机无 RDMA 设备（RNIC 驱动未加载）；`RDMA device '...' was not found` / `RDMA port ... is not active` = `roce_hca_name` 指定的设备不存在 / 缺省选中的第一个设备不可用——显式配置 `roce_hca_name` 为可用设备（本机可用设备经 `ibv_devices` 查询）。
