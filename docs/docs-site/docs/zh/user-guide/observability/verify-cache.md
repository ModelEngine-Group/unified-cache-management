# 验证外部缓存

服务启动后，用同一组请求确认：第一次计算产生可保存的块，新进程能够读取这些块，并得到正确的输出。这样可以将外部存储复用与引擎进程内缓存区分开。

## 准备一次可重复的运行

- 使用独立测试命名空间，避免清理共享的业务缓存。
- 固定模型和 tokenizer 修订、KV dtype、并行设置、块大小及 UCM 配置。
- 准备完全相同的提示词，使长度超过几个完整块。固定采样参数，并保留请求与输出。
- 开启指标并确认采集路径。[指标设置](metrics.md)说明 vLLM 的导出方式；SGLang 按 [SGLang 快速开始](../quick_start/index.md#sglang)观察。

## 首次请求：生成并保存

1. 通过引擎的健康与模型接口确认服务就绪，然后发送请求。
2. 等待缓存保存任务结束，检查 UCM 日志中的后端选择、保存活动和错误。
3. 对文件系统后端，确认出现提交的 KV 文件。健康探测也会生成小文件，应结合日志判断对象来源。

任务提交或耗时计数增加只表示该路径执行过。将成功完成、错误和后续重放结合起来，才能判断保存结果。

## 保留外部数据，重启后重放

停止测试服务后保留外部数据，以相同配置重新启动，再发送同一提示词。进程重启可以清除引擎内存缓存；若部署使用跨进程存活的共享主机缓存，还需确认它是否被保留，并根据要测量的存储层选择对应检查。

对 vLLM 的 `Cache|Posix` 路径，检查以下组合：

| 观察 | 用途 |
| --- | --- |
| `ucm:ucm_hit_tokens_total` 在本次运行中增加 | Scheduler 查询发现可复用外部 token |
| 加载任务完成，且没有对应的加载错误 | Worker 取得所需数据 |
| Posix 任务活动与文件系统读操作 | 需要确认文件后端被访问时使用 |
| 输出内容或任务分数符合基线 | 验证缓存重放的正确性 |

`cache_posix_load_success_shards_total` 统计等待主机缓冲后交付的分片，不能单独确定后端是 Posix。`posix_*` 任务计数也可能包括失败任务。具体口径见[指标参考](metrics-reference.md)。计数器随进程重启归零，比较同一次运行中的增量。

## 跨节点与 PD

跨节点共享时，在另一实例上重放，确认它访问同一存储且使用兼容布局。共享存储 PD 分离部署 还需观察 Prefill 保存结果对 Decode 的可见性；传输连接器与 UCM 组合则分别检查 P/D 交接与 Prefill 的 UCM 复用。参见[PD 分离部署](../capabilities/pd-disaggregation/index.md)。

## 结果不符合预期时

没有外部命中时，先检查提示词 token、模型与布局、完整块范围和实际存储命名空间；命中但加载失败时，检查后端健康、文件可见性、传输错误和资源预算。详细入口见[故障排查](../../reference/troubleshooting.md)。

复用正确后，再比较冷运行、外部缓存重放与内存热缓存。报告实际命中、读取路径、时延和吞吐，不用单次响应更快替代缓存验证。
