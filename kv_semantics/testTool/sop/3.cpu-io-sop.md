# 3. CPU IO 功能测试 SOP

put / get / exist / delete 四操作 IO 功能验证的简明操作步骤（**CPU-over-RoCE 真实数据面**，
IO 真实发送至对端 KV store；单实例）。构建细节见 `sop/0.build-and-run-sop.md`；建链失败
报错读法见 `sop/1.cpu-connect-disconnect-sop.md`。

前置：

- 按 `sop/0` 完成 CPU 模式编译（`bash scripts/build-kv-link.sh` 缺省模式，FAKE 与 RoCE 双
  provider 一并编入——conf 改 `transport.provider_type` 即切换，无需重编），产物 `build/testTool`
- 对端 KV store 就绪（M800、M900 监听端口可达，store 侧 RoCE 配置 `asu_roce_*` 前缀已按
  环境就位，参考 `kv_semantics/docs/guide/roce-provider.md`）
- 本机 RDMA 设备可用（`ibv_devices` 可查询到）

## 1. 配置与输入说明

test 侧配置零改动即可运行，kv client 侧为已预置真实链路的 demo 配置（只改占位值）：

| 文件 | 用途 |
| --- | --- |
| `conf/demo_cpuio_test_config.conf` | testTool 侧 IO 功能测试配置（不需改）：`testmode=2`（输入带 value）、`perf=off`（输出全量明细）、`buffertype=cpu`（主机内存值缓冲）、`onlyconnect=off`（建链后下 IO）、日志落独立目录 `log/demo_cpu/`（不与交付配置的 `log/` 混用） |
| `conf/demo_cpuio_kv_client.conf` | kv client 侧真实链路配置（已预置 `provider_type=CPU`、`send_response=true`（CPU 数据路径必配，语义见 `conf/kv_client.conf` 模板段注释）与 RoCE 传输段），**使用前按其头注释改两处占位值**：① `asu_info.1` 的对端 IP / port；② `transport.roce_gid_index`（必填，本机组网相关）；建议显式改 `transport.roce_hca_name` 为可用设备（`ibv_devices` 查询） |
| `input/demo_input.txt` | 输入序列（逐条用意见下表） |

输入逐条用意（`put ns key offset length 种子串`；`sleep` 控制节奏，保证 put 异步写在对端落盘后再读）：

| 条目 | 用意 |
| --- | --- |
| `put tenant 1111111111111111 0 512 hello world` | 写入 key1（value 512 字节，种子串在首部） |
| `put tenant 2222222222222222 0 512 npu kv test` | 写入 key2 |
| `get tenant 1111111111111111 0 512` | 读回 key1——value 首段应为种子串（写读往返一致） |
| `exist batch ns=tenant`（key1、key2 两行，`/batch` 结束） | 批量存在性查询 |
| `delete tenant 2222222222222222 0 512` | 删除 key2 |
| `get tenant 2222222222222222 0 512` | 删后读回 key2——应未命中 |

ns 是请求级 namespace 名（字符串，demo 用 `tenant` 演示）：随请求传给 kv client 并哈希派生协议帧 namespace id，**须与对端 KV store 的 namespace 名一致**（M800 为 Ceph pool 名）——不同 ns 即对端不同 namespace（数据隔离）。**ns 必填非空**（单 key 行四字段、batch 头必带 ns）：空串也会派生出独立的 namespace id（"空名字的 namespace"，并非对端缺省 namespace），缺 ns 或空 ns 的 input 启动即报错；对端单 namespace 部署时须写对端实际 namespace 名。

## 2. 运行

testTool 目录下执行（前台运行，`log.console=on` 控制台同步可见，跑完自动退出）：

```bash
KV_LOG_TO_FILE=off KV_LOG_LEVEL=debug ./build/testTool conf/demo_cpuio_test_config.conf conf/demo_cpuio_kv_client.conf input/demo_input.txt
```

> 临时备注：当前 kv client 日志输出有问题，无法正常输出文件，故执行命令统一配置
> `KV_LOG_TO_FILE=off`（kv client 不输出本地日志文件）与 `KV_LOG_LEVEL=debug`（kv client 日志
> 走控制台）；修复后移除此备注。

## 3. 结果判定

（1）退出码 0，主日志出现完成标记：`======Test Completed Successfully=======`。

（2）四操作明细齐全（主日志在 `log/demo_cpu/`，请求明细在其 `request/` 子目录），逐项核对：

| 明细 | 文件 | 行数 | 核对点 |
| --- | --- | --- | --- |
| put | `request/other_*.log` | 2 行 | `return batch code (0)`；value 以种子串开头（`hello world` / `npu kv test`），其后为预填填充 |
| get | `request/get_*.log` | 2 行 | 命中行 `key code (0)` 且 value 以种子串开头（对端读回一致）；删后行 `key code (259)`（未命中）且 value 为预填哨兵串 `unknownvaluebeforegetrequest`（无数据覆盖，证明确实没读到数据） |
| exist | `request/other_*.log` | 1 行聚合 | `all_block_ids[1111111111111111,2222222222222222]` 含两个 key |
| delete | `request/other_*.log` | 1 行聚合 | `all_block_ids[2222222222222222]` 含被删 key |

明细样例（格式参考，真实链路下各字段值以对端 KV store 行为为准，过长部分以 … 略）：

```text
(put), ns (tenant), return batch code (0), key code (0), inputkey (1111111111111111), key+offset (…), offset (0), len (17), tail (AAAAAAAA), value (hello worldAAAA…)
(get), ns (tenant), return batch code (0), key code (0), inputkey (1111111111111111), key+offset (…), offset (0), len (17), tail (AAAAAAAA), value (hello worldAAAA…)
(exist), ns (tenant), all_block_ids[1111111111111111,2222222222222222] key_high[…] prefix_hit_len (1)
(delete), ns (tenant), all_block_ids[2222222222222222] key_high[…] prefix_hit_len (-)
```

字段说明：value 为读回的缓冲首段（种子串在首部，其余为预填字节）+ 尾 8 字节 `tail`；
`len` 为纯显示字段（key 低 64 位与 offset 两十进制串位数和，无长度含义）；exist / delete
聚合行的 `prefix_hit_len` 为 kv client 返回的前缀命中 key 数（delete 无此信息以 `-` 占位）。

## 4. 排障

见 `sop/0.build-and-run-sop.md`。

| 需求 | 方法 |
| --- | --- |
| 建链失败（AddGroup FAILED / Connection refused / timed out / roce_gid_index 等） | 报错读法见 `sop/1` 末节 |
| kv client 建链与收发细节排障 | 运行命令已统一配置 `KV_LOG_TO_FILE=off KV_LOG_LEVEL=debug`（kv client 日志仅控制台输出，原因见第 2 节备注） |
| testTool 日志级别 | 改 `conf/demo_cpuio_test_config.conf` 的 `log.level`（debug / info / warn / error） |
| 值缓冲容量不足（put 失败） | 确认 `buffersize` 不小于 input 单条最大 `length`、`buffercount` 不小于单任务最大 entry 数 |
