# 4. NPU IO 功能测试 SOP

`buffertype=npu` 的 NPU 内存通路 + **HCCP KV-over-RoCE 真实数据面** IO 功能验证：值缓冲走
ACL NPU 设备内存分配 / MR 注册 / D2H 读回（`aclrtMalloc` 等），IO 真实发送至对端 KV store。
IO 功能覆盖与判定标准同 `sop/3.cpu-io-sop.md`；建链断链验证与算子库部署细节见
`sop/2.npu-connect-disconnect-sop.md`（详细 ABI 契约与算子库要求见
`kv_semantics/docs/guide/hccp-kv-over-roce-provider.md`）。

前置：

- 本机为 NPU 机器，CANN（ascend-toolkit）已安装并 `source <CANN>/set_env.sh`
  （`$ASCEND_HOME_PATH` 有值）
- **HCCP 算子库三个 so 同目录就位**：`libhccp_kv_over_roce.so`（主体）+
  `librdma_kv_send_kernel.so` / `librdma_kv_wait_kernel.so`（send / wait 算子内核）——
  部署要点见 `sop/2` 第 2 节
- 对端 KV store 以 HCCP KV-over-RoCE 后端就绪（监听端口可达，store 侧
  `asu_hccp_kv_roce_*` 配置已按环境就位）
- 按第 1 步以 NPU 模式编译（`TESTTOOL_ENABLE_ASCEND=ON`）；未编入时启动即报错退出
  （fail-fast，不做主机内存模拟——见第 2 节）

## 1. 编译（NPU 模式）

在 testTool 目录下执行统一构建脚本的 NPU 模式（编译 kv client + testTool，与 CPU 模式共用
同一脚本，详细参数说明见 `sop/2` 第 1 节；构建类型缺省 Release）：

```bash
bash scripts/build-kv-link.sh --mode npu
```

脚本内置前置检测：CANN 环境就绪（`$ASCEND_HOME_PATH` 有值且能找到 `acl/acl.h`）、
libibverbs 就绪、HCCP 与 RoCE 两个 provider 构建开关在位，不满足即报错退出并给出提示。
testTool 侧 `TESTTOOL_ENABLE_ASCEND=ON` 后 `buffertype=npu` 走真 ACL NPU 分配。

## 2. 配置说明

test 侧零改动即可运行，kv client 侧为已预置 HCCP 链路的 demo 配置（只改占位值）：

| 文件 | 说明 |
| --- | --- |
| `conf/demo_npuio_test_config.conf` | testTool 侧（不需改）：与 CPU demo 配置（`sop/3` 第 1 节）仅两处差异——`buffertype=npu`（值缓冲为 ACL DEVICE 内存）、`deviceid=0`（ACL device 编号，多卡环境按实际设备改）；日志落独立目录 `log/demo_npu/` |
| `conf/demo_npuio_kv_client.conf` | kv client 侧 HCCP 链路配置（已预置 `provider_type=HCCP_KV_OVER_ROCE`），**使用前按其头注释改三处占位值**：① `transport.hccp_kv_roce_lib_path` 算子库主体绝对路径（两个内核 so 须与主体同目录）；② `asu_info.1` 的 `local.comm_id` / port 对端 IP 与端口；③ `transport.device_id` 本机 NPU 卡号 |
| `input/demo_input.txt` | 同 CPU demo（逐条用意与 ns 语义见 `sop/3` 第 1 节） |

**误用 CPU 模式产物运行本配置**（testTool 未编 `TESTTOOL_ENABLE_ASCEND`）时启动直接报错退出：

```text
Scheduler: create value buffer allocator failed: buffertype=npu requires TESTTOOL_ENABLE_ASCEND build
(rebuild with -DTESTTOOL_ENABLE_ASCEND=ON -DTESTTOOL_ASCEND_ROOT=<CANN dir>, or bash
scripts/build-kv-link.sh --mode npu); host-memory simulation is removed, use buffertype=cpu
for host-memory testing
```

这是 fail-fast 设计（主机内存模拟已移除——模拟会让测试者误以为 NPU 链路已测通，实际没有真
NPU 内存分配）。见到该报错即说明配置已正确触达 npu 路径，按第 1 步重编即可。

## 3. 运行

testTool 目录下执行（前台运行，跑完自动退出）：

```bash
KV_LOG_TO_FILE=off KV_LOG_LEVEL=debug KV_LOG_RATE_LIMIT_ENABLE=false ./build/testTool conf/demo_npuio_test_config.conf conf/demo_npuio_kv_client.conf input/demo_input.txt
```

> 临时备注：当前 kv client 日志输出有问题，无法正常输出文件，故执行命令统一配置
> `KV_LOG_TO_FILE=off`（kv client 不输出本地日志文件）与 `KV_LOG_LEVEL=debug`（kv client 日志
> 走控制台）；修复后移除此备注。

- `KV_LOG_RATE_LIMIT_ENABLE=false`：关闭 kv 日志按调用点限流（缺省同一调用点 60s 窗口内最多 3 条、超出静默丢弃——多节点建链时 Init 日志会缺条）

## 4. 结果判定

同 `sop/3` 第 3 节（退出码 0、完成标记、四操作明细逐项核对），日志目录为 `log/demo_npu/`。
get 命中行的 value 是经 ACL D2H 从 NPU 内存读回的——value 首段为种子串即 NPU 内存通路
（分配 / 注册 / 写 / 读回）全通，且数据经 HCCP 链路与对端 store 完成真实往返。

## 5. 排障

见 `sop/0.build-and-run-sop.md` 与 `sop/2` 第 6 节（HCCP 建链内部链路与报错读法）。kv client
日志已随运行命令统一配置（`KV_LOG_TO_FILE=off KV_LOG_LEVEL=debug`，仅控制台输出，原因见第 3
节备注）；testTool 日志级别改 `conf/demo_npuio_test_config.conf` 的 `log.level`。

H2D/D2H 拷贝报 `aclrtMemcpy ... failed: 107002`（ACL_ERROR_RT_CONTEXT_NULL，驱动日志特征
`ctx is NULL`）= 调用线程无 ACL 设备上下文——ACL 设备绑定是线程级的，仅主线程绑定过时
worker 线程的拷贝即报此错。当前版本值缓冲分配器已在每次拷贝前自动校验并绑定线程设备
（`src/worker/device_allocator.cc` 的 `EnsureThreadDevice`）；若仍报，多为旧二进制——重新
编译后再跑。
