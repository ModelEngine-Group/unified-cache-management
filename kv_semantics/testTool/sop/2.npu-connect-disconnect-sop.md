# 2. NPU 建链断链 SOP

HCCP KV-over-RoCE（NPU 数据面）建链 / 断链验证的简明操作步骤。详细 ABI 契约与算子库要求见
`kv_semantics/docs/guide/hccp-kv-over-roce-provider.md`（随 HCCP provider 分支合入）。

**前置**

- 本机为 NPU 机器，CANN（ascend-toolkit）已安装并 `source <CANN>/set_env.sh`（`$ASCEND_HOME_PATH` 有值）
- 代码为含 HCCP provider 的分支（PR #1698 已合入 feature_26A_kvclient，含该合入的分支均适用）
- **HCCP 算子库三个 so 同目录就位**（见 §2）：`libhccp_kv_over_roce.so`（主体）+
  `librdma_kv_send_kernel.so` / `librdma_kv_wait_kernel.so`（send / wait 算子内核）
- 对端 KV store 以 HCCP KV-over-RoCE 后端就绪（监听端口可达，store 侧 `asu_hccp_kv_roce_*` 配置已按环境就位）

## 1. 编译

在 testTool 目录下执行统一构建脚本的 NPU 模式（编译 kv client + testTool；与 1 号 CPU SOP 共用同一脚本 `scripts/build-kv-link.sh`，CPU/NPU 差异只在模式参数与编译参数处；构建类型缺省 Release——产物可随时性能测试，调试构建显式加 `--build-type debug`）：

```bash
bash scripts/build-kv-link.sh --mode npu
```

脚本内置前置检测：CANN 环境就绪（`$ASCEND_HOME_PATH` 有值且其下能找到 `acl/acl.h`）、libibverbs 就绪（三 provider 产物编入 RoCE）、当前分支含 HCCP 与 RoCE 两个 provider 构建开关，不满足即报错退出并给出提示。以下两小节为脚本执行的等价命令与参数说明（排障或手工分步执行时参考）。

### 1.1 kv client（HCCP + RoCE + FAKE 三 provider 编入）

脚本等价命令：

```bash
cmake -S .. -B ../build-kv \
    -DRUNTIME_ENVIRONMENT=ascend \
    -DCMAKE_BUILD_TYPE=Release \
    -DBUILD_KV_CLIENT_PROVIDER_HCCP_KV_OVER_ROCE=ON \
    -DBUILD_KV_CLIENT_PROVIDER_ROCE=ON \
    -DBUILD_KV_CLIENT_PROVIDER_FAKE=ON \
    -DKV_CLIENT_CANN_ROOT=$ASCEND_HOME_PATH
cmake --build ../build-kv --target kv_client -j
```

- `BUILD_KV_CLIENT_PROVIDER_HCCP_KV_OVER_ROCE` **强制要求** `RUNTIME_ENVIRONMENT=ascend`（否则配置期 FATAL_ERROR）
- RoCE 与 FAKE 一并编入属一键脚本行为（三 provider 共存一份产物，conf 改 `transport.provider_type` 即在 FAKE / CPU-over-RoCE / HCCP 三种链路间切换无需重编）；RoCE 编入需要系统 libibverbs（`libibverbs-dev`），脚本前置检测已覆盖
- `KV_CLIENT_CANN_ROOT` 缺省即依次取 `$ASCEND_HOME_PATH` → `$ASCEND_ROOT` →
  `/usr/local/Ascend/ascend-toolkit/latest`（显式传首选项更直观）；配置期在其下找
  `acl/acl.h` 与 `libascendcl.so`（覆盖 lib64 / lib / runtime / aarch64-linux 多种布局），找不到报错
- 产物：`build-kv/src/libkv_client.so` + `libkv_transport.so`（三种 provider 编入后者，
  HCCP 运行时依赖链 `libkv_transport.so → libascendcl.so`）

### 1.2 testTool（真 NPU 内存分配——实际测试 NPU 链路时必加）

执行本 SOP 即实际测试 NPU 链路，以下编译参数为必备步骤（不加则 NPU 内存注册被拒，建链断链验证无法完成）。脚本等价命令（`-I` 路径取实际命中 CANN 头文件布局的目录：x86 通常为 `$ASCEND_HOME_PATH/include`，aarch64-linux 布局时为 `$ASCEND_HOME_PATH/aarch64-linux/include`，脚本自动检测）：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_CXX_FLAGS="-DTESTTOOL_ENABLE_ASCEND -I$ASCEND_HOME_PATH/include"
cmake --build build -j
```

- **为什么必加**：HCCP provider 的 RegisterMemory 只接受 NPU 设备内存（host 描述符直接
  `INVALID_ARGUMENT`）。`TESTTOOL_ENABLE_ASCEND` 编入后 `buffertype=npu` 走真 ACL NPU 分配
  （`aclrtMalloc`）；不编入则打 WARN 回退主机内存模拟——注册被算子库拒绝，**建链断链验证无法完成内存注册**
- `aclrt*` 符号经链接链上的 `libkv_transport.so → libascendcl.so` 解析，**前提是 build-kv 为
  HCCP 构建**（§1.1）；若 kv client 为非 HCCP 构建，此处链接会报未定义符号
- 注意：testTool 的 CMakeLists 目前无该宏的正式开关入口，先经 `CMAKE_CXX_FLAGS` 注入（待后续补 option）

## 2. so 依赖清单

| so | 来源 | 阶段 | 作用 |
|---|---|---|---|
| `libascendcl.so` | CANN（`$ASCEND_HOME_PATH` 下 lib 目录） | **编译链接** + 运行时 | ACL 设备 / 上下文管理（`aclrtSetDevice` 等），`libkv_transport.so` 的 DT_NEEDED |
| `libhccp_kv_over_roce.so` | HCCP 算子库（随环境分发，如 `/opt/hccp/`） | **运行时加载**（kv client dlopen） | 算子库主体：拥有 QP / MR / RDMA 资源，CreateConnection、RegisterMemory、Send；必须导出 `Init` 等必需符号，`GetAbiVersion` 若导出须返回 1 |
| `librdma_kv_send_kernel.so` | HCCP 算子库目录（**与主体同目录**） | 运行时（算子库内部加载） | send 算子内核（发起 IO 的 AIV 内核），kv client 代码不感知；对应 InitConfig 的 `send_aiv_count` |
| `librdma_kv_wait_kernel.so` | HCCP 算子库目录（**与主体同目录**） | 运行时（算子库内部加载） | wait 算子内核（等待 / 完成轮询的 AIV 内核），kv client 代码不感知；对应 InitConfig 的 `wait_aiv_count` |

部署要点：

- **算子库三个文件必须放在同一目录**（`libhccp_kv_over_roce.so` 按其内部约定在同目录加载
  两个内核 so；ABI 无内核路径字段，分目录放置算子库无法找到内核）
- `libascendcl.so` 由 CANN 环境提供，正常 `source set_env.sh` 后即在搜索路径上
- 算子库主体的查找顺序：`transport.hccp_kv_roce_lib_path` → 环境变量
  `UCM_HCCP_KV_ROCE_LIB_PATH` → 动态链接搜索路径（缺省名 `libhccp_kv_over_roce.so`）

## 3. 修改配置文件

复制 `conf/kv_client.conf` 为独立 NPU 配置（如 `conf/kv_client_hccp.conf`，HCCP 模板段已内置），按下表改：

| 文件 | 键 | 值 |
|---|---|---|
| NPU kv client 配置 | `transport.provider_type` | `HCCP_KV_OVER_ROCE` |
| | `transport.device_id` | NPU 卡号（如 0；缺省先取当前 ACL 设备再 0） |
| | `transport.hccp_kv_roce_lib_path` | 算子库主体绝对路径，如 `/opt/hccp/libhccp_kv_over_roce.so`；**该目录下须同时放两个内核 so**（见 §2 部署要点） |
| | `transport.hccp_kv_roce_max_connections` | 缺省 3072（QPC HBM 槽数，512B/槽 ≈ 1.5MiB，可不写） |
| | `asu_info.N` | `protocol=TCP,local.comm_id=<对端IP>,port=<对端端口>`（**注意：对端 IP 填在 `local.comm_id` 字段**，provider 取该字段作 remote IP；留空被拒） |
| | `view.config_path` | 指向 view 副本 |
| view 副本（复制 `conf/kv_client_view.conf`） | — | **必须与上表同步**：`asuIds` 与 `asu_info.N` 完全一致——建链端点最终以 view 为准（同 1 号 SOP） |
| test conf 副本（复制 `conf/test_config.conf`） | `onlyconnect` / `buffertype` / `deviceid` | `on` / `npu` / 0（真 NPU 分配，配合 §1.2） |

进阶：`transport.hccp_kv_roce_<field>` 可覆盖算子 InitConfig（`mem_size` 640MiB、`timeout_ms`
60000、`sdk_ioq_depth` 128 等，字段表见 guide）——缺省即可跑通建链，仅调优时使用。

## 4. 启动（建链验证）

```bash
KV_LOG_LEVEL=debug ./build/testTool <test conf 副本(onlyconnect=on)> conf/kv_client_hccp.conf
```

- 建链成功标志同 1 号 SOP：`onlyconnect=on: connection established, waiting for Ctrl+C to
  exit...`（N 个节点全部建链成功才挂起，任一失败直接报错退出）
- HCCP 建链内部链路（日志可逐段对上）：provider 构造（ACL 上下文捕获 → HBM 槽区分配 → 算子库
  dlopen + `Init`）→ `CreateConnection`（算子建 manager + QP，QPC 写入 HBM 槽）→ view 全端点完成
- 结束：`Ctrl+C` 优雅断链（断链走算子 `DeleteConnections`，释放 QP 与 HBM 槽）

## 5. 断链与观察

同 1 号 SOP：test conf 副本的 `autodisconnect = 30`（建链成功 n 秒后自动断链，
进程不退出供观察），观察完毕 `Ctrl+C`。

## 6. 失败报错读法

| 报错（关键片段） | 原因与处理 |
|---|---|
| `requires RUNTIME_ENVIRONMENT=ascend` | kv client 编译参数缺 `-DRUNTIME_ENVIRONMENT=ascend` |
| `Cannot find acl/acl.h / libascendcl under KV_CLIENT_CANN_ROOT` | CANN root 路径不对 / 未 source CANN 环境（`$ASCEND_HOME_PATH` 为空） |
| `UNSUPPORTED ... enable BUILD_KV_CLIENT_PROVIDER_HCCP_KV_OVER_ROCE` | kv client 编译未开 HCCP 宏——provider 是空壳（缺宏构建时占位实现） |
| provider 构造 `NOT_FOUND`（library load） | `hccp_kv_roce_lib_path` 路径错 / 算子库缺 `Init`、`CreateConnection`、`DeleteConnections`、`RegisterMemory` 任一必需导出符号 |
| 算子库主体加载成功、`Init` 阶段失败（报错来自算子库内部） | 算子库目录下内核 so 缺失：`librdma_kv_send_kernel.so` / `librdma_kv_wait_kernel.so` 须与主体**同目录**（§2 部署要点），确认三个文件齐全 |
| `INTERNAL_ERROR` + ABI version | 算子库导出 `GetAbiVersion` 但返回值 ≠ 1（与 provider ABI 版本不符，换配套算子库） |
| 注册被拒 `INVALID_ARGUMENT`（MEM_HOST） | testTool 未编 `TESTTOOL_ENABLE_ASCEND`（host 模拟注册）或 `buffertype` 没设 `npu` |
| 建链 `RESOURCE_BUSY` | QP 数超出 `hccp_kv_roce_max_connections` 槽容量（调大该键） |
| testTool 链接期 `undefined reference to aclrt...` | build-kv 非 HCCP 构建（`libascendcl.so` 不在链接链上）——按 §1.1 重编 kv client |
