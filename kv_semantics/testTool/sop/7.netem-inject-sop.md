# testTool SOP：网络延迟/丢包故障注入（netem）

长稳测试中模拟网络劣化（延迟 / 抖动 / 丢包 / 带宽限制），观察 testTool 的 P99 时延分位、错误率与恢复行为（配合 sop/6 的 P99 行与 Prometheus/Grafana 看板实时观察）。工具为 `scripts/netem-inject.sh`（tc netem，目标 Linux 机器执行）。

## 第一部分：生效矩阵（选错设备注入无效）

netem 工作在内核网络栈 egress，**只对经过内核的流量生效**：

| 链路类型 | 是否生效 | 注入点 |
| --- | --- | --- |
| TCP / UDP | 完全生效 | 实际通信网卡 |
| SoftRoCE（rxe） | 生效 | rxe 绑定的底层网卡（`rdma link show` 查绑定，脚本自动提示） |
| 硬件 RoCE / InfiniBand（mlx5、Hi1822 等） | **不生效** | verbs 数据面 kernel-bypass 不走内核 qdisc；延迟/丢包需在交换机或对端机器注入（脚本检测到会警告） |
| FAKE | 无效 | 进程内模拟不经网络栈 |

## 第二部分：用法

```bash
bash scripts/netem-inject.sh show [dev]            # 查看注入状态（缺省全部网卡 + RDMA 概览）
bash scripts/netem-inject.sh add <dev> [参数...]   # 注入（replace 语义，重复执行覆盖）
bash scripts/netem-inject.sh del <dev>             # 清除注入恢复链路
```

| 参数 | 说明 |
| --- | --- |
| `--delay 5ms` | 单向延迟（--jitter 存在时为均值） |
| `--jitter 1ms` | 延迟抖动（须配 --delay；--dist 选分布） |
| `--loss 0.1` | 丢包率 %（RoCE 链路建议 0.01 ~ 1 起步） |
| `--corr 25` | 延迟/丢包时间相关性 %（模拟突发式劣化） |
| `--rate 100mbit` | 可选：同步限制发送带宽 |
| `--limit 100000` | 可选：netem 队列长度（包数；默认放大到 10 万——内核默认 1000 在高 IOPS 注入延迟时会打满产生计划外丢包） |

## 第三部分：与 testTool 配合观察

- **观察点**：日志 P99 行（`p99_interval_s` 周期）、`/metrics` 端点（`metrics_exporter=on`）、Grafana 看板（sop/6 第三部分 PromQL）
- **建议注入梯度**：延迟 5ms → 50ms → 500ms；丢包 0.01% → 0.1% → 1%（`--corr 25~50` 模拟突发）。每档观察至少一个 P99 打印周期再调档
- **预期形态**：P99 先于均值恶化（长尾请求最先受影响）；`ratelimit_mb` 是应用层提交限速、本脚本是线路注入限速，两者叠加可观察排队放大效应

## 第四部分：权限

- 需 root 或 `CAP_NET_ADMIN`；容器场景需 `docker run --cap-add NET_ADMIN`（普通容器默认无此权限，`tc` 报 Operation not permitted）
- 注入在本机**发送侧**（egress），只影响出向流量；回程方向劣化需在对端机器执行

## 第五部分：常见问题

| 现象 | 处理 |
| --- | --- |
| 硬件 RoCE 网卡上注入后指标无变化 | 预期行为：verbs 数据面 kernel-bypass，netem 不生效（见第一部分矩阵） |
| 丢包注入后 P99 暴涨甚至超时 | RoCE RC 丢包恢复为 go-back-N 整段重传，语义远比 TCP 剧烈——降丢包率（0.01% 起步） |
| 高 IOPS 下未注入丢包却出现丢包 | 队列打满：调大 `--limit`（默认已 10 万） |
| `tc: command not found` | 安装 iproute2（容器镜像未预置时：`apt-get install -y iproute2`） |
| 注入不生效 | 确认设备名（`show` 列出全部网卡）；确认流量走该网卡 egress；确认容器有 NET_ADMIN |

## 验证记录（2026-11-28，--cap-add NET_ADMIN 容器实测）

- 延迟：`add eth0 --delay 5ms --jitter 1ms --corr 25` 后 ping 网关 RTT 0.075ms → 4.931ms（精确生效），`del` 恢复 0.057ms
- 丢包：`add eth0 --loss 20 --corr 25` 后 ping 20 包统计丢包率符合设定
- 参数校验：`--delay 5xx` / `--loss 200` / `--corr 100` / 不存在网卡均正确报错退出非零；无注入时 `del` 不动现有 qdisc
